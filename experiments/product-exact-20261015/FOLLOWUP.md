# Independent exact follow-ups, 16 October 2026

These experiments start from immutable external four-stage streams, never the
coordinator's live qualification trees. They are component diagnostics pending
complete replay, source port, frozen census and unchanged official benchmark.
They do not search nonces or modify gate content using sampled input behavior.

- `follow-chain-20261016`: seven predetermined stages, retained128, retained512,
  retained1024, plain ANF512, retained128, retained512, retained1024. Same pair
  expansion64 and product cap1M as the frozen chain. Product and wide run one
  thread each. The final operation and measurement-map reconstruction includes
  every preceding stage and compares original quantum values, bits, phase and
  scratch on independent and structured packets.
- `scratch-20261016`: preserved failed launcher (compiler absent from PATH).
  `scratch-v2-20261016` loads the normal compiler environment. New exact allocator
  offers eight fresh zero quantum slots after existing clean donors. Only the
  wide objective may use this width increase. A new exhaustive native regression
  passed all quantum input, classical guard and dirty phase patterns. Caps
  128/512/1024/2048 each start from the immutable four-stage wide stream.
- `unfold-20261016`: inverse definitions for retained large XOR IDs. The new
  normalizer unfolds only an XOR with at most16 atoms and total definition
  length at most4 times the atom cap. Symmetric difference is exact, constants
  remain outside definitions, and clearing the two bounded caches loses proofs
  only. Native cancellation/complement tests and an independent distributive
  witness simulation are required before any full-stream transformation.
- `pair-expansion-20261016`: exact ANF expansion budget256/1024 pairs with atom
  cap128/512; all eight fixed product/wide configurations start from their
  immutable four-stage streams and undergo complete replay. This changes the
  amount of exact symbolic proof search, never the inherited arithmetic cuts.

Each launcher records its PID, exit status, resource preflight and dedicated
logs. Library threads remain one; new builds use at most four threads. None of
these counts are new scored records.
